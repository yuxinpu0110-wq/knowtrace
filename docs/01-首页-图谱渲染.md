# 环节 1：首页 / 知识图谱渲染（1号）

## 这个环节做什么

进入系统后的初始界面：左侧是用户当前知识图谱（占页面大部分），右侧只有两个按钮「编辑」「提问」。

- 图谱由 `react-force-graph-2d` 渲染，节点颜色/亮度由前端 JS 根据状态和 BFS 距离计算。
- 点选节点：右侧显示该节点的只读卡片。
- 空状态（还没有图谱）时，左侧显示引导，点「去编辑」跳到 `/edit`。

## 负责的文件

- `frontend/src/views/HomeView.tsx` —— 右侧面板（两个按钮 + 选中节点卡片）。
- `frontend/src/components/GraphPanel.tsx` —— 图谱渲染（力导向布局、点选回调）。
- `frontend/src/graph/paintNode.ts` —— 单个节点的画布绘制（颜色/亮度/半径）。
- `frontend/src/graph/lighting.ts` —— 状态颜色表 `STATE_COLORS`、标签 `STATE_LABELS`、亮度函数 `brightness(d)`。
- `frontend/src/graph/bfs.ts` —— `bfsDistance(graph, seedId)` 计算各节点到种子的 BFS 距离（前端算，不让模型算）。
- `frontend/src/App.tsx` —— 布局（图谱在左、控制面板在右）。

## 节点状态与颜色（`NodeState`）

| 状态 | 颜色 | 含义 |
|------|------|------|
| `inactive` | 灰 | 未激活 |
| `question_related` | 蓝 | 与题目相关（种子） |
| `suspected_gap` | 橙 | 疑似薄弱点（仅提示） |
| `mastered` | 绿 | 已掌握 |
| `recommended` | 紫 | 推荐关注 |

亮度随 BFS 距离衰减：`brightness(d) = max(0.15, 0.72^d)`。

## 点选联动的约定

`App.tsx` 里 `handleNodeSelect(id)`：
- 在 `/test` 且诊断已完成（`state.diagnosisDone`）时 → `chooseToLearn(id)`（进入学习）；
- 在 `/` 且处于「直接学习」模式（`state.directLearn`）时 → `chooseToLearn(id)`（进入学习）；
- 其余情况 → `selectNode(id)`（仅选中显示卡片）。

### 首页「直接学习」（跳过提问与诊断的入口）

右侧面板除「提出问题」「当前知识图谱」外，还有「直接学习」按钮：

- `useFlow.goDirectLearn()` 清空本次提问链路并置 `directLearn: true`，停在 `/`，右侧出现提示卡片（含「退出」）。
- 之后点图谱任一节点 → 与诊断完成后**完全同一条** `chooseToLearn` → `/learn`，教学、检测、点亮逻辑全部复用，无新增链路。
- `directLearn` 是一次性 UI 态，在 `chooseToLearn`、`resetAskTransient`、`loadGraphRecord` 中都会被清掉，不会残留到下次进入首页。
- 无图谱时按钮禁用（没有可选节点）。

#### ⚠️ 两个必须遵守的隐含前提（都踩过）

直接学习跳过了 `graph/generate` 与 `question/locate`，而这两个请求原本承担着**把图谱登记到后端共享状态**的副作用（`adapters/state.js`）。因此：

1. **`teachingGenerate` 必须随请求带上 `graph`。** 后端 `adapters/teaching.js` 用的是跨请求共享的 `getGraph()`；不带图谱时 `node` 为 `null`，`if (hasKey() && node)` 整段 DeepSeek 教学分支被静默跳过，降级成硬编码 `TEACHINGS` 表，表里没有的节点直接给「（示例占位）」。`server.js` 的 `/api/teaching/generate` 与 `question/locate` 一致：`if (requestGraph?.nodes?.length) setGraph(requestGraph)`。**新增任何依赖 `getGraph()` 的入口都要照此办理。**
2. **`/learn` 的「返回」不能硬编码回 `/test`。** 原来的 `handleBack` 把 `/learn → /test` 写死了，这个假设只对「诊断后学习」成立；直接学习按返回会掉进一个空的诊断页（`diagnosisDone=false`、`currentQuestion=null`，页面卡在「第 1 轮」且没有任何选项）。现由 `learnOrigin` 在 `chooseToLearn` 里按入口记录（`/test` 或 `/`），`actions.backFromLearn()` 据此回退。

「直接学习」是一次性选点态：`chooseToLearn` 会把它置回 `false`，所以从 `/learn` 出来的所有出口（顶部「返回」、「退出学习」、学完的「返回知识图谱」）都落到同一个普通首页，想再学一个节点需重新点「直接学习」。

## 验收清单

1. 空状态：左侧显示「还没有知识图谱」，点「去编辑 →」跳到 `/edit`。
2. 有图谱：左侧正常渲染；右侧「编辑」「提问」两个按钮都能跳转。
3. 点选节点：右侧出现该节点卡片，名字/章节/摘要正确，状态徽章颜色正确。
4. 已掌握节点：`masteredIds` 里的节点显示绿色。
5. 缩放/拖拽图谱不崩溃；窗口 resize 自适应。
6. 控制台无报错；`npm run build` 通过。

## 注意

### ⚠️ 已知陷阱：force-graph 会原地改写 edges（务必遵守）

`react-force-graph`（v1.51.4，`dist/force-graph.mjs` 第 856-859 行）会**原地改写传进去的 link 对象**，随后 d3-force 把 `link.source` / `link.target` 从 **id 字符串**替换成**节点对象**：

```js
state.graphData.links.forEach((link) => {
  link.source = link[link.source];
  link.target = link[link.target];
});
```

后果（都踩过）：
- `bfs.ts` 邻接表按字符串 id 匹配 → **边全部被跳过** → `distanceMap` 只剩种子 → 其余节点 `on=0` **整片不可见**（表现：「点了下节点颜色全没了」）。
- `removeNode` 用 `e.source !== id` 过滤 → 匹配不上 → **删节点留下悬空边**。

两条防护（都已实施，不要撤掉）：
1. `GraphPanel.tsx` 传给 `ForceGraph2D` 的 links 必须是**副本**：`graph.edges.map((e) => ({ ...e }))`；`nodes` 可以共享（力的 x/y 写回是有益的）。
2. `bfs.ts` 的 `endId()` 同时接受 id 字符串与节点对象两种端点形式（兜底）。

新增任何「读 `graph.edges`」的代码时，都用 `endId()` 取端点，不要直接拿 `e.source` 当字符串比较。

- **不要在浏览器端接触 API Key / 完整 Prompt / 模型原始输出**（本环节不涉及模型调用，天然满足）。
- 渲染性能：`nodeCanvasObject` 每帧调用，避免在其中做重计算（BFS/亮度已用 `useMemo` 缓存）。
