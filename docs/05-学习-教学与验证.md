# 环节 5：学习 / 教学与验证（6号）

## 这个环节做什么

`/learn` 页面：对用户在诊断完成后点选的节点做单节点教学，然后出一道验证题，答对后把该节点点亮为绿色（加入 `masteredIds`），用户数据更新，返回首页。

- 进入 `/learn` 前，`chooseToLearn(nodeId)` 已先 `navigate('/learn')` 并调 `teachingGenerate` 生成教学内容。
- 用户答验证题 → `teachingEvaluate` 判分 → `suggested_state==='green'` 则点亮并进入完成页。

## 负责的文件

- `frontend/src/views/LearnView.tsx` —— 教学内容展示 + 验证题 + 完成页。
- `frontend/src/flow/useFlow.ts` —— `chooseToLearn`、`evaluateAnswer`。
- `frontend/src/api/api.ts` —— `teachingGenerate`、`evaluate`。
- `backend/adapters/teaching.js` —— 6号教学（DeepSeek 生成教学内容 + 确定性判分）。
- `backend/mocks/teaching.js` —— `mockTeachingGenerate`、`mockEvaluate`（无 key/失败降级）。

## 教学契约（6号）

- `POST /api/teaching/generate` 输出：`{ node_id, definition, intuition, relation, example, pitfall, verify_question }`。
- **`expected_answer` 不得返回前端**（答案只存后端 `specCache`，供验证判分用）。
- `POST /api/teaching/evaluate` 输出：`{ node_id, mastery: 'mastered'|'partial'|'not_mastered', score, evidence, suggested_state: 'green'|'orange'|'gray' }`。
- 判分是**确定性**的（对比 `specCache`/硬编码答案），不让模型算分。

## 验收清单

1. 诊断完成后点左侧任一节点 → 跳到 `/learn`，顶部显示「学习：<节点名>（章节）」。
2. 依次显示：定义、直观理解、联系、例题、易错点，LaTeX 正确渲染。
3. 验证题显示后输入答案 → 「提交验证」→ 出现评估结果。
4. 答对（`suggested_state==='green'`）→ 显示「学习完成 ✅」+「返回首页」；左侧图谱该节点变绿。
5. 点「返回首页」→ 回到 `/`，右侧仍是「编辑」「提问」两按钮；已掌握节点保持绿色（`masteredIds` 持久于本次会话）。
6. 答错 → 评估提示「还需巩固」，可修改答案重试。
7. 后端日志出现 `[adapter] teaching/generate`、`teaching/evaluate`；无 key 回退 Mock 也能跑通。

## 注意

- 教学内容的 `node_id` 必须真实存在；`expected_answer` 绝不能出现在前端响应或浏览器网络面板里。
- 点亮逻辑：`evaluateAnswer` 里 `suggested_state === 'green'` 才把 `node_id` 加入 `masteredIds`；`lastLearnedId` 触发完成页。
