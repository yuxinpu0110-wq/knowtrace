# 环节 4：诊断 / 选择题多轮追问（5号）

## 这个环节做什么

`/test` 页面：对用户做 **2~5 道**前置知识追问，每轮一道选择题（3 个选项 + 「模糊」「不会」两个按钮），根据回答更新候选薄弱节点置信度；**每轮把多个候选薄弱点（`weak_points`）的置信度反馈回图谱**——橙红色亮度随各自置信度逐轮增强（带缓动动画，多个薄弱点同时点亮、越亮越薄弱），最终给出**疑似薄弱点（仅提示）**。

- 用户在第 1 轮开始前，`submitQuestion` 已先调 `diagnosisNext(round=0)` 拿到第一题。
- 每轮回答后调 `diagnosisNext(round, question, answer, signal)`，`done` 或第 3 轮结束即诊断完成。
- 完成后显示薄弱点卡片，提示用户**在左侧图谱上点选想学的节点**（不强制，用户自己决定）。

## 负责的文件

- `frontend/src/views/TestView.tsx` —— 诊断 UI（选择题 / 自由文本兜底 / 结果卡片）。
- `frontend/src/flow/useFlow.ts` —— `answerDiagnosis`（透传 signal，判断终轮）。
- `frontend/src/api/api.ts` —— `diagnosisNext(round, question, answer, signal?)`。
- `backend/adapters/diagnosis.js` —— 5号诊断（DeepSeek 生成选择题 + 判分 + 置信度更新）。
- `backend/mocks/diagnosis.js` —— `mockDiagnosisNext`（无 key/失败降级，含 canned `next_options`）。

## 选择题契约（5号，核心）

- 每题输出 `next_options: { text: string; signal: 'correct'|'fuzzy'|'dontknow' }[]`，**恰 3 项**：
  - `correct` = 正确；`fuzzy` = 似是而非（半错）；`dontknow` = 明显错误。
  - 顺序随机（后端再 Fisher-Yates 打乱一次）。
- 判分（`FACTOR` 表，前端不参与计算，后端算）：
  - `correct` 0.35（降置信）、`partial` 0.7、`wrong` 1.5、`fuzzy` 1.1、`dontknow` 1.45。
- `diagnosisNext({ round, question, answer, signal, seed_nodes })`：`signal` 在 `{correct,fuzzy,dontknow}` 内直接采用，否则走原关键词启发式判分。
- 每轮输出 `weak_points: { node_id, confidence }[]`（多个薄弱点，供前端多点橙红点亮）；终局输出 `suspected_gap`（置信度最高的那个）。所有 `node_id` 必须来自图谱，不得造假。

## 验收清单

1. 进入 `/test`，显示第 1 题 + 3 个选项按钮（A/B/C）+「模糊」「不会」。
2. 选项含数学公式时用 LaTeX 正确渲染（`MathMarkdown`）。
3. 点选项 → 进入下一轮；每轮左侧图谱**多个薄弱点**橙红色亮度随各自置信度增强（带动画）；2~5 轮后显示「诊断完成」+ 薄弱点卡片（名字、置信度）。
4. 「模糊」「不会」按钮分别以 `fuzzy`/`dontknow` signal 提交。
5. 无 `next_options`（自由文本兜底）时显示文本框，输入提交也能推进。
6. 后端日志出现 `[adapter] diagnosis/next …`；无 key 时回退 Mock，仍 2~5 轮可跑完。
7. 薄弱点 `node_id` 能在图谱中找到；找不到即违规。

## 注意

- **薄弱点只是提示**，不强制用户学它；用户点哪个节点学哪个（由 `App.tsx` 的 `handleNodeSelect` + `/test` 判断处理）。
- 每轮一次 DeepSeek 调用，最多 5 次（2~5 道题）；加超时避免挂起，超时/非法输出回退模板题（自由文本，`next_options=null`）。
- 选择题 signal 与置信度映射不得错：correct 降、fuzzy/dontknow 升。
- 后端**每轮**返回多个薄弱点 `weak_points`（`runningWeakPoints`，置信度 ≥ 0.25 的前 5 个），前端据此做多点逐轮亮度动画；终局的 `suspected_gap` 仍以 `finalize` 的阈值结果为准。
