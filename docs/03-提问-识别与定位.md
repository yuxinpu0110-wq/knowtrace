# 环节 3：提问 / 识别与定位（3号识别 + 4号定位）

## 这个环节做什么

`/problem` 页面输入一道题 → 提交后依次调用「识别」和「定位」，定位出题目相关的图谱节点（种子节点），随后自动跳到 `/test` 进入诊断。

- 输入支持 **Markdown + LaTeX（`$...$`）**，也允许自然语言；页面有「识别预览」自动渲染 Markdown。

- **3号 识别**：`POST /api/question/recognize`，输入 `{ text }`，输出题目结构化信息（当前因 OCR 缺失用文字兜底，仍为 Mock）。
- **4号 定位**：`POST /api/question/locate`，输入 `{ recognized_question }`，输出相关节点 `{ seed_nodes }`。

## 负责的文件

- `frontend/src/views/ProblemView.tsx` —— 提问输入 + 识别结果展示。
- `frontend/src/flow/useFlow.ts` —— `submitQuestion`（串起 recognize → locate → diagnosisNext → navigate('/test')）。
- `frontend/src/api/api.ts` —— `recognize`、`locate` 封装。
- `frontend/src/api/mocks/recognize.ts`、`frontend/src/api/mocks/locate.ts` —— `mockRecognize`、`mockLocate`（无 key/失败降级用）。
- `backend/adapters/locate.js` —— 4号定位（DeepSeek 选节点 / 关键词 fallback）。
- `backend/server.js` —— `/api/question/recognize`、`/api/question/locate` 路由。

## 定位契约（4号，重要）

- 输出：`{ seed_nodes: [{ node_id, relevance, reason }] }`，选 1~3 个最相关节点。
- **`node_id` 必须来自当前图谱的节点集合**（`backend/adapters/state.js` 的 `getGraph()`），不得造图谱外 id。
- 非法 `node_id` 一律丢弃，最多保留合法节点；全非法则回退关键词匹配。

## 验收清单

1. 输入题目 → 「提交问题」→ 后端日志出现 `[adapter] question/locate …`。
2. 识别结果块显示学科、置信度、题目正文（`problem_markdown`）。
3. 提交成功后自动跳到 `/test`，左侧图谱**所有定位到的相关节点都被点亮为蓝色**，亮度与其 `relevance` 正相关（最高约 50%，主相关节点带白环），同时仍按 BFS 逐层点亮相邻节点作上下文。
4. `seed_nodes` 的每个 `node_id` 都能在图谱里找到对应节点；找不到说明定位违规。
5. 无 key 或定位失败 → 走 `mockLocate`，链路不崩，仍能进入 `/test`。

## 注意

- 识别目前是 Mock（`server.js` 里 `/api/question/recognize` 直接返回 `mockRecognize`）。3号接真实 OCR 时，只需改这一处 + `backend/adapters/` 新增识别适配器，**不要改前端契约字段**。
- 定位的 node_id 校验是红线：宁可少选，不可乱造。
