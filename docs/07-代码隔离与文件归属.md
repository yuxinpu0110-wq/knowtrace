# 代码隔离与文件归属（防止互相覆盖）

> 本项目**没有 git**，团队直接共享目录，所以「两个人改同一个文件 → 合并时互相覆盖」是最大风险。本文件定义**每个文件归谁改**，并已把最容易冲突的 Mock 文件拆成「每环节一个文件」。

## 三条铁律

1. **只改自己名下的文件**（见下表「独有」列）；别人的文件一律不碰。
2. **「共享冻结」文件只有 7号（整合）能改**。任何环节需要改这些文件时，走「提需求给 7号」或「新增自己的文件让 7号接线」，不要自己直接改。
3. **合并（收口）由 7号 统一做**：7号 只做「接线 + 拼文件」，不重写他人文件的内容。

## 不碰共享文件，也能扩展（配方）

### 后端新增一个接口（以 3号 接真实识别为例）
1. 在 `backend/adapters/recognize.js` 写真实实现（只写自己文件）。
2. 在 `backend/mocks/recognize.js` 写 Mock（只写自己文件）。
3. **不要改 `backend/server.js`**。把「需要在 server.js 接线」的需求写清楚（路由路径、入参、出参），提交给 7号，由 7号 加一行 `app.post(...)` 接线。

### 后端新增 Mock 内容（5/6号）
- 直接改 `backend/mocks/diagnosis.js` / `backend/mocks/teaching.js`。
- `backend/mock.js` barrel 用 `export *` 自动导出，**新增函数无需改 barrel**。

### 前端新增 Mock 内容
- 直接改 `frontend/src/api/mocks/<环节>.ts`。
- `frontend/src/api/mock.ts` barrel 用 `export *` 自动导出，无需改。

### 需要改共享文件（useFlow / api / types / server）时
- 只允许 7号 动手。其他人：把要加的字段/接口写清（字段名、类型、含义），在群里提给 7号。
- 契约字段**只能加可选字段**，不改已有字段（保证其他人不崩）。

## 收口（合并成新版本）步骤

1. 各人只交自己「独有」文件的最新版（不改动的独有文件可以不交）。
2. 7号 收集后：按上表把每个独有文件放回对应位置。
3. 7号 在自己的「共享冻结」文件上做接线（新增路由、字段、barrel export）。
4. 跑 `cd frontend && npm run build`（tsc + vite）确认类型无误；跑后端 `npm start` 全链路手测。
5. 出问题只回滚到「谁的文件谁修」，不回滚别人的文件。

## 冲突急救

- 若发现两个人都改了同一文件：**以「独有」那一方为准**；共享文件以 7号 版本为准。
- 冲突内容不要硬拼，贴出来让 7号 判断。
