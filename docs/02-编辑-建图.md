# 环节 2：编辑 / 导入教材建图（2号）

## 这个环节做什么

`/edit` 页面做两件事：

1. **导入教材生成图谱**：粘贴教材 Markdown → 调用后端 `POST /api/graph/generate` → 得到知识图谱。
2. **节点状态管理（简化版）**：点击节点可选择「删除」或「标为已掌握」；也可手动添加节点（名称 + 章节）。

## 负责的文件

- `frontend/src/views/EditView.tsx` —— 编辑页 UI（导入块 + 节点列表 + 选中节点操作）。
- `frontend/src/flow/useFlow.ts` —— `generateGraph`、`addNode`、`removeNode`、`toggleMastered`、`setTextbook`、`loadSampleTextbook`。
- `backend/adapters/graph.js` —— 后端建图适配器（真实 DeepSeek / 规则 fallback）。
- `2.module-2-md2graph/demo/generate_graph.py` —— 真实 DeepSeek 建图脚本。
- `2.module-2-md2graph/demo/mock_generate_graph.py` —— 离线规则建图脚本（fallback，与 contracts 金标对齐）。

## Markdown 规约（教材格式）

```
# 书名
## 章节
### 小节
#### 知识点：<知识点名>
```

- `例题：`、`易错点：` 是干扰段，不生成节点。

## 后端逻辑（`backend/adapters/graph.js`）

- `useReal = hasKey() && GRAPH_REAL !== '0'`：有 key 走真实 DeepSeek 建图（超时放宽到 180s），否则走规则脚本。
- 输出必须满足 `{ nodes: [...], edges: [...] }`，`node.id` 匹配 `^[a-z0-9_]+$`，`edge.relation ∈ prerequisite|contains|related|contrast`。
- 无 key 或失败 → 规则脚本产出金标图（20 个线性代数知识点，node_id 与 `contracts/graph.example.json` 对齐）。

## 验收清单

1. 「加载示例教材」按钮能加载 `public/textbook.md` 到文本框。
2. 「生成图谱」后，左侧图谱出现节点，数量 > 0；后端日志出现 `[adapter] graph/generate 真实模块完成`（有 key）或 `失败，回退 Mock`（无 key）。
3. 节点列表：能搜索、点选高亮；已掌握节点带 ✅。
4. 选中节点：点「标为已掌握」→ ✅ 出现、图谱节点变绿；再点「取消已掌握」恢复。
5. 选中节点：点「删除节点」→ 节点及其相关边从图谱和列表消失。
6. 「添加节点」输入名称+章节 → 新节点出现（id 自动生成，不冲突）。
7. 生成的 `node_id` 不得与图谱现有 id 冲突；不得创造非法 id。

## 注意

- 新增的 `node.id` 必须是 `[a-z0-9_]`；由 `useFlow.ts` 的 `genNodeId` 统一生成。
- 手动添加的节点要有合法 `source` 字段（`{ heading:'手动添加', start_line:0, end_line:0 }`）。
- 建图脚本的 key 通过环境变量 `DEEPSEEK_API_KEY` 传入（由后端 `runPython` 的 env 合并），脚本内不要写死 key。
