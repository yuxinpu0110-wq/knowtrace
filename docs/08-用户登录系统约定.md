# 用户登录系统约定（登录负责人 + 7号 对接）

> 有一位队员要接入用户登录。本文件约定**登录怎么接、文件归谁、和现有 5 环节怎么衔接**，避免登录改乱主链路。

## 一、登录的定位

- 登录是**入口门禁**：进入主应用之前完成，登录成功后的初始界面 = 用户当前知识图谱（首页 `/`）。
- **登录不改变 5 个环节的内部逻辑**：`/edit` `/problem` `/test` `/learn` 这四页一个字节都不要为了登录而改。
- 登录要解决的核心是「**用户当前知识图谱**」：图谱（含已掌握节点）按用户区分，登录后从后端加载。

## 〇、实现记录（2026-09-12，7号）

### 背景：`Login_added` 里没有登录界面

对 `Login_added/project` 与本项目做全量 diff，结果是**只有 1 个新增文件**：

```
Only in Login_added/project/frontend/src/api/auth.ts
```

没有 `LoginView.tsx`、没有 JSX/CSS、后端也没有任何 auth 路由；其 `dist` 包里也搜不到登录代码。
即队友交付的仅是**一个 API 封装文件**，且它 `import { apiPost, API_AVAILABLE } from './mock'`
在本项目里**无法编译**（`API_AVAILABLE` 不存在，`apiPost` 在 `./client`）。

因此「接入队友的登录界面」无法照字面执行。经确认后由 7号 **按本文件约定自行实现登录页 + 用户存储**，
并**保留队友 `auth.ts` 的导出名与接口路径**，他日他交付真正的 UI 时可直接替换 `views/LoginView.tsx`。

### 实际实现

| 层 | 文件 | 说明 |
|---|---|---|
| 后端存储 | `backend/adapters/users.js` | 账号（scrypt 哈希 + salt）+ 每用户进度，落盘 `backend/data/store.json` |
| 后端接口 | `backend/server.js` | `/api/auth/{login,logout,me,register}`、`/api/user/{load-progress,progress}` |
| 前端 API | `frontend/src/api/auth.ts` | 沿用队友导出名：`login/logout/getStoredUser/setStoredUser/fetchUserProgress/saveUserProgress` |
| 前端状态 | `frontend/src/flow/useAuth.ts` | 登录态 hook（含刷新后校验 Cookie 会话） |
| 登录页 | `frontend/src/views/LoginView.tsx` | 门禁页；换成队友的 UI 只需替换此文件 |
| 接线 | `frontend/src/App.tsx`、`router.ts`、`flow/useFlow.ts` | 门禁、`/login` 路由、`hydrate()` 灌入用户图谱 |

- **所有认证接口都是 POST**（本项目 `apiPost` 只支持 POST，与队友契约一致）。
- 会话：`kt_session` Cookie，**HttpOnly + SameSite=Lax**，值为 HMAC 签名的无状态令牌（7 天，后端重启不失效）。
- 密码：`scrypt` 哈希 + 随机 salt 落盘，接口只回 `{username, displayName, role}`，**从不回传哈希/salt/令牌**。
- 进度中 `masteredIds` 保存时按该用户图谱的 `node_id` **强制过滤**（实测图谱外 id 会被丢弃），沿用「不造图谱外 id」红线。
- **防数据丢失**：登录后先用 `hydrate()` 载入用户图谱，载入完成（`progressLoaded`）前**禁止回写**，避免用空状态覆盖已保存进度。
- 数据目录可用 `KT_DATA_DIR` 覆盖；`backend/data/` 是运行时状态，不随交付分发。

### 演示账号（已确认保留在前端 Mock）

7 组演示账号同时存在于两处：
1. 后端 `users.js` 的 `DEMO_ACCOUNTS`（首次启动写入 `store.json`，**只存哈希**）；
2. 前端 `api/auth.ts` 的 `DEMO_USERS`，**仅在后端不可用时**作为兜底登录。

⚠️ 已知代价（用户已确认接受）：前端兜底列表中的密码会出现在浏览器 bundle 里，任何人可查看。
真实登录路径不受影响（走 httpOnly Cookie + 后端校验）。若要消除该代价，删掉 `auth.ts` 里的 `DEMO_USERS`
并去掉 `login()` 的兜底分支即可，后端演示账号不受影响。

### 验收结果（实测）

错误密码 401 / 正确密码返回用户且无哈希 / Cookie 为 HttpOnly / `me` 正常 /
初始进度为 `null` / 保存后读回一致 / 图谱外 id 被过滤 / 无 Cookie 401 / 登出后 401 / 中文往返一致 —— 全部通过。

## 二、文件归属（登录负责人独有）

登录负责人只新建/只改下面这些文件，**不要动** `useFlow.ts` / `server.js` / `App.tsx` / `router.ts` / `types.ts`：

- 前端：`frontend/src/views/LoginView.tsx`（登录页）
- 前端：`frontend/src/api/auth.ts`（登录/注册/取用户图谱等接口封装）
- 后端：`backend/adapters/auth.js`（登录校验、发令牌、用户图谱存取）
- 后端：`backend/mocks/auth.js`（无 key/后端不可用时的登录 Mock）

> 需要「路由 `/login`」「登录态拦截」「登录后往 useFlow 灌初始图谱」这些接线动作，由 **7号** 在共享文件里做（下面第四节列好接缝），登录负责人把接口和数据结构提供给 7号 即可。

## 三、接口与数据契约（登录负责人实现，7号 接线）

建议接口（路径可协商，字段如下；**图谱字段复用现有 `GraphData`**，不要另造）：

| 接口 | 入参 | 出参 |
|------|------|------|
| `POST /api/auth/login` | `{ username, password }` | `{ user: { id, name } }`（令牌走 httpOnly cookie） |
| `POST /api/auth/logout` | — | `{ ok: true }` |
| `GET /api/auth/me` | — | `{ user }` 或 401 |
| `GET /api/user/graph` | — | `{ graph: GraphData, mastered_ids: string[] }`（空则 `graph: null`） |
| `POST /api/user/graph` | `{ graph: GraphData, mastered_ids: string[] }` | `{ ok: true }` |

- **`mastered_ids` 必须 ⊆ 当前图谱的 node_id 集合**，非法 id 后端要丢弃（沿用「不造图谱外 id」红线）。
- 用户图谱为空时返回 `graph: null`，前端仍显示「还没有知识图谱」空状态。

## 四、与现有代码的接缝（由 7号 做，登录负责人只提供接口）

1. **路由**：`router.ts` 增加 `/login`；未登录访问其它路由时 `App.tsx` 重定向到 `/login`。
2. **登录态**：`useFlow` 增加 `user` 与「加载用户图谱」动作；登录成功后调用 `GET /api/user/graph` 灌入 `state.graph` + `state.masteredIds`。
3. **保存时机**：当 `state.graph` 或 `state.masteredIds` 变化（生成图谱、标为已掌握、点亮节点）时，调用 `POST /api/user/graph` 保存（可节流/在离开页面时保存）。
4. **登录页样式**：复用现有 `App.css` 的主题变量（`--bg/--panel/--accent`），不新造配色。

## 五、会话 / 令牌安全（红线）

- 令牌放 **httpOnly + SameSite cookie**，**不要放 localStorage / sessionStorage**（防 XSS 读取）。
- 令牌里**不得**包含 API Key、完整 Prompt、模型原始输出。
- 密码只做哈希后落库（即使 hackathon 也**不存明文密码**）。
- 后端持有 `DEEPSEEK_API_KEY` 的方式不变（`adapters/key.js`，内存 + 环境变量），**登录 token 与 API Key 彻底分开**。
- 登录校验放**后端**（`backend/adapters/auth.js`），前端登录页只是表单，不做前端伪装的安全判断。

## 六、游客模式（保证其它环节调试不受登录影响）

- 必须保留**「跳过登录 / 游客模式」**入口：不登录也能进首页走完整 5 环节（图谱用内置 `public/graph.example.json`，不存用户数据）。
- 这样 1~6号 调试时**不需要注册账号**，登录负责人调试时单独开 `/login`。
- 游客模式下不调 `POST /api/user/graph`（避免把游客图谱写进某个用户）。

## 七、验收清单（登录）

1. 打开前端 → 未登录跳转 `/login`；「游客模式」能直接进首页。
2. 登录成功后首页显示**该用户自己的图谱**（与游客图谱不同，或为空状态）。
3. 在用户态下生成图谱/标已掌握 → 刷新页面后数据还在（已持久化）。
4. 登出 → 回到 `/login`；再登录 → 数据恢复。
5. 浏览器 Cookie 里只有 httpOnly 会话 cookie，**无 API Key、无 Prompt、无明文密码**。
6. 1~6号 的环节在「游客模式」下全部正常，不受登录改动影响。
7. `npm run build` 通过，后端 `npm start` 全链路手测通过。
